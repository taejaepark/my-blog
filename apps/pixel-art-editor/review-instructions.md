# Review 서브에이전트 지침 — 픽셀 아트 에디터

## 배경
`/apps/pixel-art-editor/spec.md`에 확정된 계획대로 `index.html`, `style.css`, `script.js`가 이미 구현되어 있다. 너는 Build를 수행한 서브에이전트와는 별개의 독립적인 검증 담당이다.

## 이 작업에서 할 일
1. `/apps/pixel-art-editor/spec.md`를 읽고 구현이 계획과 일치하는지 코드를 읽어 확인한다.
2. 브라우저에서 실제로 `/apps/pixel-art-editor/index.html`을 열어(로컬 정적 서버 권장 — file://로 직접 열면 브라우저 자동화 도구가 프로젝트 폴더 밖 파일을 정적 스냅샷으로만 렌더링해 JS가 실행되지 않을 수 있으니 `python -m http.server` 등으로 로컬 서버를 띄워서 확인) 다음을 확인한다:
   - 16x16 캔버스 격자, 색상 팔레트(스와치 + 커스텀 색상 입력 + 지우개), 전체 지우기 버튼, PNG 저장 버튼, 다크모드 토글이 화면에 정상적으로 보이는지.
   - 캔버스를 클릭하면 선택된 색으로 해당 칸이 칠해지는지, 드래그하면 지나간 여러 칸이 칠해지는지.
   - 다른 색상 스와치를 클릭하면 색이 바뀌고 선택 표시가 이동하는지, 커스텀 색상 입력도 반영되는지.
   - 지우개 모드에서 칠하면 해당 칸이 지워지는지(투명/빈 칸).
   - 전체 지우기 버튼이 격자를 초기화하는지.
   - PNG 저장 버튼을 클릭했을 때 실제로 다운로드가 트리거되는지(브라우저 자동화 도구의 다운로드 감지가 어려우면, 코드를 읽어 `toDataURL('image/png')` → `<a download>` 클릭 로직이 spec.md 6번 항목과 정확히 일치하는지 검토하는 것으로 대체 가능. 가능하다면 콘솔에서 저장 함수를 직접 호출해 반환되는 데이터 URL이 `data:image/png`로 시작하는지 확인해보는 것도 좋다).
   - 다크모드 토글 클릭 시 테마가 바뀌고, 새로고침 후에도 유지되는지.
   - 모바일 폭(예: 375px)으로 리사이즈했을 때 레이아웃이 겹치거나 잘리지 않는지.
   - 콘솔에 에러가 없는지 확인.
3. spec.md의 "9. 검증 계획" 항목들을 하나씩 대조해 확인한다.
4. 검증 결과를 `/apps/pixel-art-editor/review.md`에 작성한다 — 확인한 항목과 결과(정상/문제)를 목록으로 정리.
5. **문제를 발견하면 네가 직접 수정한다.** 수정한 내용도 review.md에 기록한다.

## 범위 제한
- `/apps/pixel-art-editor/` 폴더 밖의 파일은 수정하지 않는다.
- spec.md에 없는 새 기능을 추가하지 않는다. 발견한 버그를 spec.md의 의도에 맞게 고치는 것만 한다.
- `plan-instructions.md`, `spec.md`, `build-instructions.md`는 그대로 둔다.

## 완료 조건
- `/apps/pixel-art-editor/review.md`가 작성되어 있다.
- 발견된 문제가 있었다면 수정이 반영되어 있고, review.md에 "무엇을 왜 고쳤는지"가 기록되어 있다.
- 문제가 없었다면 review.md에 "문제 없음"으로 명확히 기록한다.

작업이 끝나면 review.md의 핵심 내용(발견된 문제와 수정 여부)을 요약해서 보고해라.
