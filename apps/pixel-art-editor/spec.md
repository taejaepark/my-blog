# 픽셀 아트 에디터 구현 계획 (spec)

## 1. 기능 개요

- 16x16 격자 위에 도트(칸)를 클릭 또는 드래그로 찍어 그림을 그리는 미니 웹앱.
- 화면 한쪽의 색상 팔레트에서 색을 선택하면, 이후 찍는 도트는 그 색으로 칠해짐.
- 완성한 그림을 PNG 이미지 파일로 저장(다운로드)할 수 있음.
- 마우스(클릭/드래그)와 터치(탭/드래그) 모두로 그릴 수 있어야 하며, 모바일 화면에서도 격자가 알맞게 축소되어 사용 가능해야 함.
- 범위 밖 기능(레이어, 실행취소/다시실행, 다중 프레임 애니메이션, 이미지 불러오기 등)은 포함하지 않는다.

## 2. 파일 구조

`/apps/pixel-art-editor/` 폴더 안에 아래 3개 파일만 생성한다. 블로그 본체나 다른 앱의 파일(assets/css/style.css 등)은 일절 참조하지 않고, 이 앱은 완전히 자체 완결적이어야 한다.

- `index.html`: 마크업 (제목, 격자를 그릴 `<canvas>`, 색상 팔레트, 커스텀 색상 선택 `<input type="color">`, 지우개 버튼, 전체 지우기 버튼, PNG 저장 버튼, 다크모드 토글 버튼). `style.css`, `script.js`를 상대 경로로 로드.
- `style.css`: 레이아웃, 팔레트 스타일, 다크모드 변수, 반응형 스타일 전부 포함.
- `script.js`: 도트 데이터 상태 관리, 캔버스 렌더링, 마우스/터치 입력 처리, 색상 선택, PNG 내보내기 로직을 모두 포함하는 순수 바닐라 JS.
- 외부 라이브러리/CDN은 사용하지 않는다. PNG 저장은 브라우저 내장 `<canvas>`의 `toDataURL('image/png')`만으로 충분히 구현 가능하므로 별도 라이브러리가 필요 없음.

## 3. 격자/캔버스 설계

**결정: 격자는 DOM 요소(16x16 `<div>`) 대신 단일 `<canvas>` 하나로 렌더링한다.**

검토한 두 방식과 이유:

- **DOM 방식(16x16개 `<div>`)**: 셀마다 이벤트를 걸 수 있어 클릭 판정은 직관적이지만, PNG로 저장하려면 결국 이 DOM 상태를 다시 `<canvas>`에 그려서 `toDataURL`을 호출해야 하므로 렌더링 로직이 두 군데(DOM 스타일 + canvas 그리기)로 중복된다. 256개의 DOM 노드는 16x16 규모에서는 성능 문제가 크지 않지만 불필요한 복잡도를 추가한다.
- **Canvas 방식(선택)**: 도트 데이터(16x16 배열)를 캔버스 하나에 그리는 함수 하나만 있으면, 화면 표시와 PNG 저장(6번 항목)에 동일한 그리기 로직 또는 동일한 데이터 소스를 그대로 재사용할 수 있다. 이벤트는 캔버스 하나에만 걸고, 클릭/터치 좌표를 셀 크기로 나누어 (row, col)을 계산하면 되므로 오히려 더 단순하다. 접근성(스크린리더) 측면에서는 DOM 방식보다 불리하지만, 그림 그리기 도구라는 앱 특성상 중요도가 낮다고 판단해 canvas 방식을 채택한다.

렌더링 방식:

- 도트 데이터는 `pixels`라는 16x16 2차원 배열(`Array(16).fill(null).map(() => Array(16).fill(null))`)로 관리. 각 칸의 값은 색상 문자열(`"#ff0000"` 등) 또는 `null`(빈 칸/투명).
- 화면에 보이는 `<canvas>`는 CSS로 정사각형 크기를 반응형으로 결정하고(`width`/`height` 속성은 표시용으로 확대된 해상도, 예: 320x320 또는 컨테이너 폭에 맞춰 JS에서 동적으로 설정), 매 그리기 동작 후 `pixels` 배열 전체를 순회하며 각 칸을 `fillRect`로 다시 그린다(칸이 `null`이면 배경색으로 채우거나 비워둠).
- 셀 사이에 옅은 격자선을 `strokeRect` 또는 별도 선 그리기로 그려 칸 구분을 시각적으로 표시한다.
- `imageSmoothingEnabled = false`로 설정해 확대된 사각형이 흐려지지 않도록 한다(사각형을 직접 그리므로 큰 영향은 없지만 안전하게 명시).

## 4. 색상 팔레트 설계

- 기본 제공 색상: 16개 내외의 실용적인 팔레트를 고정 배열로 정의한다. 예: 검정, 흰색, 회색(밝은/어두운), 빨강, 주황, 노랑, 연두, 초록, 청록, 파랑, 남색, 보라, 분홍, 갈색, 살구색 — 흔한 픽셀 아트 도구의 기본 팔레트 수준으로 과하지 않게 구성.
- 각 색상은 작은 정사각형 버튼(스와치)으로 팔레트 영역에 나열. 클릭하면 `currentColor` 상태가 해당 색으로 바뀜.
- **현재 선택된 색 표시**: 선택된 스와치에 테두리/외곽선(box-shadow 등)을 강조 표시. 별도로 "현재 색상" 미리보기 칸도 하나 두어 커스텀 색상을 골랐을 때도 확인 가능하게 함.
- **커스텀 색상**: 기본 `<input type="color">` 요소를 팔레트 옆에 하나 배치. 값이 바뀌면(`change`/`input` 이벤트) `currentColor`를 그 값으로 설정 — 별도의 커스텀 색상 팔레트 저장/추가 기능은 만들지 않는다(요청 범위 밖).
- **지우개**: 별도의 "지우개" 버튼을 팔레트 영역에 둔다. 지우개 모드가 활성화되면 이후 그리는 칸은 색상 대신 `null`(투명/빈 칸)로 설정됨. 지우개 버튼도 다른 색상 스와치와 동일한 선택 강조 방식을 공유(현재 "선택된 도구"가 색상인지 지우개인지 하나만 강조).

## 5. 그리기 상호작용

- **한 칸 클릭**: 해당 칸을 `currentColor`(또는 지우개면 `null`)로 칠하고 다시 렌더링.
- **드래그로 연속 칠하기**: 마우스 버튼을 누른 상태로 캔버스 위를 움직이면 지나가는 모든 칸이 같은 색으로 칠해짐. `isDrawing` 불리언 플래그로 현재 드래그 중인지 추적.
  - 같은 칸을 반복해서 다시 칠하는 것은 무해하므로, 드래그 중 매 `mousemove`/`touchmove`마다 좌표 → 셀 계산 후 칠하되, 렌더링은 매번 전체 다시 그리기(16x16 규모라 성능 문제 없음).
- **지우개 기능**: 위 팔레트 설계에서 설명한 대로 별도 버튼으로 모드 전환. 지우개 상태에서 클릭/드래그하면 해당 칸이 `null`로 설정되어 투명(또는 빈 배경)으로 표시됨.
- **전체 지우기 버튼**: `pixels` 배열 전체를 `null`로 초기화하고 다시 렌더링하는 버튼을 하나 둔다(2048의 "새 게임" 버튼과 유사한 역할).

## 6. PNG 저장 로직

- **원본 해상도로 저장**: 픽셀 아트 도구의 일반적인 관례에 따라, 화면에 확대되어 보이는 캔버스와 별개로 저장 시점에 16x16 크기의 오프스크린(임시) `<canvas>`를 하나 생성한다(`width=16, height=16`).
  - 이 임시 캔버스에 `pixels` 배열을 1칸=1픽셀로 그린다: 색이 있는 칸은 `fillRect(x, y, 1, 1)`, `null`인 칸은 그리지 않고 캔버스 기본 투명 배경을 그대로 둔다(→ PNG가 투명 배경을 지원).
  - 화면에 보이는 확대된 격자 그대로(예: 320x320) 저장하지 않는 이유: 실제 파일을 다른 게임/이미지 도구에서 원본 픽셀 아트 소스로 재사용하기 편하도록 하기 위함이며, 필요하면 사용자가 별도 이미지 도구에서 확대할 수 있다. 확대/축소본을 함께 저장하는 옵션은 요청 범위 밖이므로 만들지 않는다.
- **다운로드 트리거**: 임시 캔버스의 `toDataURL('image/png')` 결과를 얻은 뒤, 메모리 상에서 `<a>` 요소를 하나 생성해 `href`에 그 데이터 URL을, `download` 속성에 `"pixel-art.png"` 같은 파일명을 지정하고 `a.click()`을 호출해 다운로드를 트리거한다. 이후 해당 `<a>` 요소는 DOM에 붙이지 않았다면 별도 정리가 필요 없다(붙였다면 `remove()`).
- Blob/`URL.createObjectURL` 방식은 사용하지 않는다 — 16x16 이미지는 매우 작아 `toDataURL` 데이터 URL 직접 사용으로 충분히 단순하고 실용적이다.

## 7. UI/레이아웃

- **배치**: 상단에 제목과 다크모드 토글 버튼. 그 아래 캔버스(격자)와 팔레트 영역을 나란히(데스크톱: 좌우 또는 캔버스 중심 + 팔레트 하단, 모바일: 세로로 쌓임) 배치. 팔레트 영역에는 색상 스와치들, 커스텀 색상 `<input type="color">`, 지우개 버튼이 함께 있고, 그 아래(또는 옆)에 "전체 지우기"와 "PNG로 저장" 버튼을 둔다.
- **다크모드**: 블로그 본체와 독립적으로 이 앱 자체적으로 지원한다(파일을 공유하지 않으므로). CSS 커스텀 프로퍼티(`--bg`, `--text`, `--panel-bg`, `--grid-line` 등)를 `:root`에 정의하고, `prefers-color-scheme: dark` 미디어쿼리로 자동 전환 + `data-theme` 속성을 이용한 수동 토글 버튼을 둔다. 토글 상태는 이 앱 전용 localStorage 키(예: `theme-pixel-art-editor`)에 저장해 재방문 시 유지 — 2048 앱과 동일한 패턴을 따르되 과도하게 확장하지 않는다.
- **반응형/모바일 레이아웃**: 캔버스의 CSS 크기(`width`/`height` 스타일, 실제 `canvas.width/height` 속성과는 별개)를 뷰포트 폭에 따라 `min(90vw, 400px)` 같은 방식으로 정사각형 유지하며 축소. 팔레트 스와치는 `flex-wrap`으로 좁은 화면에서 자동 줄바꿈. 버튼들은 좁은 화면에서 세로로 쌓이거나 넉넉한 터치 영역(최소 44px 정도)을 갖도록 함.

## 8. 입력 처리

- **마우스**: `mousedown`(해당 칸 칠하고 `isDrawing = true`), `mousemove`(`isDrawing`이 true일 때만 좌표의 칸을 칠함), `mouseup` 및 캔버스 밖으로 나가는 `mouseleave`에서 `isDrawing = false`로 리셋(창 전체의 `mouseup`도 함께 리스닝해, 캔버스 밖에서 버튼을 뗀 경우도 안전하게 처리).
- **터치**: `touchstart`(해당 칸 칠하고 `isDrawing = true`), `touchmove`(터치 좌표로 칸을 계산해 칠함), `touchend`/`touchcancel`에서 `isDrawing = false`.
  - 터치로 그림을 그릴 때 페이지가 스크롤되지 않도록, 캔버스 자체에 CSS `touch-action: none`을 지정하고 `touchmove` 핸들러에서 `e.preventDefault()`를 호출한다.
- 마우스 좌표 → 셀 인덱스 변환: 캔버스의 `getBoundingClientRect()`로 캔버스 기준 상대 좌표를 구한 뒤, 캔버스의 CSS 표시 크기를 16으로 나눈 셀 크기로 나누어 `(col, row)`를 계산(0~15 범위를 벗어나면 무시).

## 9. 검증 계획

구현 완료 후 아래 항목을 확인하여 완성 여부를 판단한다.

1. **도트 찍기**: 캔버스의 각 칸을 클릭하면 선택된 색으로 정확히 그 칸만 칠해지는지 확인.
2. **드래그로 연속 칠하기**: 마우스 버튼을 누른 채 여러 칸을 가로지르면 지나간 칸들이 모두 같은 색으로 칠해지고, 버튼을 떼거나 캔버스 밖으로 나가면 더 이상 칠해지지 않는지 확인.
3. **색상 변경**: 팔레트의 다른 스와치를 클릭하면 이후 그리는 칸의 색이 바뀌고, 선택 표시(강조 테두리)가 올바른 스와치로 이동하는지 확인. 커스텀 색상(`<input type="color">`)을 바꿔도 동일하게 반영되는지 확인.
4. **지우개**: 지우개 모드에서 칠하면 해당 칸이 투명/빈 칸으로 바뀌는지 확인.
5. **전체 지우기**: 버튼 클릭 시 격자 전체가 초기화되는지 확인.
6. **PNG 저장**: 저장 버튼 클릭 시 실제로 유효한 PNG 파일이 다운로드되고, 이미지 뷰어로 열었을 때 16x16 해상도로 그렸던 그림과 투명 영역(빈 칸)이 올바르게 나타나는지 확인.
7. **모바일 터치**: 터치 탭과 드래그로 그림을 그릴 수 있고, 그리는 동안 페이지가 스크롤되지 않는지 확인.
8. **반응형 레이아웃**: 좁은 화면(모바일 너비)에서 캔버스와 팔레트/버튼이 겹치거나 화면 밖으로 잘리지 않고 정사각형 격자가 유지되는지 확인.
9. **다크모드**: 시스템 설정(`prefers-color-scheme`) 자동 반영과 수동 토글 버튼이 모두 정상 동작하고, 토글 상태가 새로고침 후에도 유지되는지 확인.
