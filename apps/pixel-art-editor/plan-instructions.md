# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 배경
이 프로젝트는 마크다운 블로그 + 미니 웹앱 포트폴리오(`/apps/{앱이름}/`)다. 사용자가 "픽셀 아트 에디터"를 요청했다. 16x16 격자에 도트를 찍어서 그림을 그리고, 완성하면 PNG로 저장할 수 있어야 하며, 색상 팔레트도 있어야 한다.

## 이 작업에서 할 일
`/apps/pixel-art-editor/spec.md`에 구현 계획을 작성한다. **코드는 절대 작성하지 않는다.** index.html, style.css, script.js 등 어떤 구현 파일도 만들지 않는다. 오직 `spec.md` 한 파일만 작성한다.

## 제약 조건 (프로젝트 CLAUDE.md)
- 프레임워크/번들러 금지. 순수 HTML/CSS/JS.
- 외부 라이브러리 최소화 (CDN은 허용되지만, PNG 저장은 브라우저 내장 `<canvas>`의 `toBlob`/`toDataURL`로 충분히 가능하므로 외부 라이브러리 없이 구현 가능한지 검토해서 spec에 명시).
- 앱은 `/apps/pixel-art-editor/` 폴더 안에 자체 완결되어야 한다 (블로그의 다른 파일 참조 금지).
- 모바일에서도 사용 가능해야 한다 — 마우스 클릭/드래그뿐 아니라 터치로도 도트를 찍을 수 있어야 한다.

## spec.md에 포함할 내용
1. **기능 개요**: 16x16 격자, 클릭(및 드래그로 연속 칠하기)으로 도트 찍기, 색상 팔레트에서 색 선택, 완성 후 PNG로 저장(다운로드).
2. **파일 구조**: `/apps/pixel-art-editor/` 안에 만들 파일 목록과 각 파일의 역할.
3. **격자/캔버스 설계**: 16x16 그리드를 어떻게 표현하고 렌더링할지 (HTML `<canvas>` 기반 vs DOM 요소 16x16개 기반 중 택1 — 각각의 장단점을 검토해 하나를 선택하고 이유를 spec에 명시). PNG로 저장해야 하므로 최종적으로 `<canvas>`를 활용하는 방식이 자연스러운지 판단할 것.
4. **색상 팔레트 설계**: 기본 제공 색상 목록(몇 개, 어떤 색), 현재 선택된 색 표시 방식, 커스텀 색상 선택(브라우저 기본 `<input type="color">` 활용 여부)을 포함할지 판단해 spec에 명시.
5. **그리기 상호작용**: 클릭으로 한 칸 칠하기, 마우스 버튼을 누른 채 드래그하면 지나간 칸들도 같은 색으로 칠해지는 동작, 지우개(배경색/투명으로 칠하기) 기능 포함 여부를 판단해 spec에 명시.
6. **PNG 저장 로직**: 16x16 도트 데이터를 실제 다운로드 가능한 PNG 파일로 만드는 방법 (예: 작은 16x16 caps `<canvas>`를 그대로 `toDataURL('image/png')`로 내보내되, 화면에 보이는 격자는 확대해서 그려도 실제 저장은 원본 16x16 해상도로 저장할지, 혹은 사용자가 보기 편하도록 확대된 크기 그대로 저장할지 — 실용적인 쪽으로 판단해 spec에 명시). 다운로드 트리거 방식(예: `<a download>` + Blob URL)도 명시.
7. **UI/레이아웃**: 격자와 팔레트의 배치, 지우기(전체 초기화) 버튼, 저장 버튼, 다크모드 지원 여부(이 앱도 독립적이므로 블로그 본체와 동일한 패턴으로 자체 판단해 명시하되 과도하게 확장하지 말 것), 반응형/모바일 레이아웃(격자 셀 크기가 화면 폭에 맞게 조정되어야 함).
8. **입력 처리**: 마우스(mousedown/mousemove/mouseup으로 드래그 칠하기)와 터치(touchstart/touchmove/touchend, 스크롤과 충돌하지 않도록 처리) 모두 지원하는 방법.
9. **검증 계획**: 구현 후 무엇을 확인해야 완성으로 볼 수 있는지(도트 찍기, 드래그로 연속 칠하기, 색상 변경, 지우기, PNG 저장이 실제 유효한 이미지 파일로 다운로드되는지, 모바일 터치, 반응형 레이아웃).

## 유의사항
- 요청받지 않은 기능(예: 레이어, 실행취소/다시실행 히스토리, 다중 프레임 애니메이션, 파일 불러오기 등)을 spec에 추가하지 말 것. 딱 요청된 범위(16x16 격자, 도트 찍기, PNG 저장, 색상 팔레트)에 집중.
- spec은 간결하되 Build 서브에이전트가 그대로 구현할 수 있을 만큼 구체적이어야 한다.
- 작업이 끝나면 `/apps/pixel-art-editor/spec.md` 파일 하나만 남기고 종료한다.
