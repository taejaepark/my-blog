# Review 서브에이전트 지침 — 2048 게임

## 배경
`/apps/2048/spec.md`에 확정된 계획대로 `/apps/2048/index.html`, `style.css`, `script.js`가 이미 구현되어 있다. 너는 Build를 수행한 서브에이전트와는 별개의 독립적인 검증 담당이다.

## 이 작업에서 할 일
1. `/apps/2048/spec.md`를 읽고 구현이 계획과 일치하는지 코드를 읽어 확인한다.
2. 브라우저에서 실제로 `/apps/2048/index.html`을 열어(로컬 정적 서버 또는 file:// 직접 열기 — 이 앱은 빌드 스텝이 없는 순수 정적 파일이라 둘 다 가능) 다음을 확인한다:
   - 4x4 게임판, 점수판(현재 점수 + 최고 점수), 새 게임 버튼, 다크모드 토글, 모바일 온스크린 방향 버튼이 화면에 정상적으로 보이는지.
   - 방향키로 타일이 이동/병합되는지, 병합 시 점수가 오르는지 (실제로 몇 번 조작해서 확인).
   - 새 게임 버튼 클릭 시 보드/점수가 초기화되는지.
   - 다크모드 토글 클릭 시 테마가 바뀌고, 새로고침 후에도 유지되는지.
   - 모바일 폭(예: 375px)으로 리사이즈했을 때 레이아웃이 겹치거나 잘리지 않는지, 온스크린 방향 버튼이 정상 동작하는지.
   - 콘솔에 에러가 없는지 확인.
3. spec.md의 "7. 검증 계획" 항목들을 하나씩 대조해 확인한다. 승리/패배 오버레이는 실제 플레이로 유도하기 어려우면, 코드 로직을 읽어서(승리: 2048 타일 등장 판정, 패배: canMove 판정) 논리적으로 타당한지 검토하는 것으로 대체해도 된다.
4. 검증 결과를 `/apps/2048/review.md`에 작성한다 — 확인한 항목과 결과(정상/문제)를 목록으로 정리.
5. **문제를 발견하면 네가 직접 수정한다** (수정도 이 Review 단계의 책임이다 — CLAUDE.md 4단계 사이클 중 "Review — ... 문제가 있으면 수정한다"). 수정한 내용도 review.md에 기록한다.

## 범위 제한
- `/apps/2048/` 폴더 밖의 파일은 수정하지 않는다.
- spec.md에 없는 새 기능을 추가하지 않는다. 발견한 버그를 spec.md의 의도에 맞게 고치는 것만 한다.
- `plan-instructions.md`, `spec.md`, `build-instructions.md`는 그대로 둔다.

## 완료 조건
- `/apps/2048/review.md`가 작성되어 있다.
- 발견된 문제가 있었다면 수정이 반영되어 있고, review.md에 "무엇을 왜 고쳤는지"가 기록되어 있다.
- 문제가 없었다면 review.md에 "문제 없음"으로 명확히 기록한다.

작업이 끝나면 review.md의 핵심 내용(발견된 문제와 수정 여부)을 요약해서 보고해라.
