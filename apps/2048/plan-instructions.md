# Plan 서브에이전트 지침 — 2048 게임

## 배경
이 프로젝트는 마크다운 블로그 + 미니 웹앱 포트폴리오(`/apps/{앱이름}/`)다. 사용자가 "2048 게임"을 요청했다. 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임이고, 점수판이 있어야 한다.

## 이 작업에서 할 일
`/apps/2048/spec.md`에 구현 계획을 작성한다. **코드는 절대 작성하지 않는다.** index.html, style.css, script.js 등 어떤 구현 파일도 만들지 않는다. 오직 `spec.md` 한 파일만 작성한다.

## 제약 조건 (프로젝트 CLAUDE.md)
- 프레임워크/번들러 금지. 순수 HTML/CSS/JS.
- 외부 라이브러리 최소화 (CDN은 허용되지만 이 게임엔 불필요할 가능성이 높음 — 필요성을 스스로 판단해 spec에 명시).
- 앱은 `/apps/2048/` 폴더 안에서 완전히 자체 완결되어야 한다 (블로그의 다른 파일 참조 금지).
- 모바일에서도 사용 가능해야 한다 — 방향키 외에 터치/스와이프 또는 온스크린 버튼 등 모바일 입력 방식도 고려해서 spec에 포함할 것.

## spec.md에 포함할 내용
1. **게임 개요**: 4x4 그리드, 2/4 타일이 랜덤 스폰, 방향키로 전체 타일을 한 방향으로 밀며 같은 숫자끼리 합쳐짐, 승리(2048 타일 등장)/패배(더 이상 이동 불가) 조건.
2. **파일 구조**: `/apps/2048/` 안에 만들 파일 목록과 각 파일의 역할 (예: index.html, style.css, script.js).
3. **게임 로직 설계**: 그리드 상태를 어떻게 표현할지(예: 4x4 배열), 이동/병합 알고리즘의 핵심 아이디어, 타일 스폰 로직, 승패 판정 시점.
4. **점수판 설계**: 현재 점수 표시 방식, 점수 계산 규칙(병합 시 두 타일 값의 합만큼 증가 등), 최고 점수(localStorage) 유지 여부 — 여부는 스스로 판단해 spec에 명시(과설계 금지, 꼭 필요하면 포함).
5. **UI/레이아웃**: 타일 색상 구분 방식(숫자별 배색), 다크모드 지원 여부(블로그 본체의 다크모드 관례를 따를지, 이 앱은 독립적이므로 자체 판단해 spec에 명시하되 과도하게 확장하지 말 것), 반응형/모바일 레이아웃, 재시작 버튼.
6. **입력 처리**: 키보드(방향키), 모바일 터치(스와이프 제스처 또는 버튼) 처리 방식.
7. **검증 계획**: 구현 후 무엇을 확인해야 완성으로 볼 수 있는지(타일 이동/병합 정상 동작, 승패 조건, 점수 갱신, 모바일 터치, 반응형 레이아웃).

## 유의사항
- 요청받지 않은 기능(예: 애니메이션 고도화, 다중 난이도, 리더보드 서버 연동 등)을 spec에 추가하지 말 것. 딱 요청된 범위(방향키로 타일 밀기, 합치기, 점수판)에 집중.
- spec은 간결하되 Build 서브에이전트가 그대로 구현할 수 있을 만큼 구체적이어야 한다.
- 작업이 끝나면 `/apps/2048/spec.md` 파일 하나만 남기고 종료한다.
