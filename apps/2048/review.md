# 2048 게임 Review 결과

Build 서브에이전트가 구현한 `index.html`, `style.css`, `script.js`를 `spec.md`와 대조하여 검증했다.
검증은 코드 정독(스펙과의 로직 대조)과, `apps/2048` 디렉터리에서 `python -m http.server`로 띄운 로컬 정적 서버를
브라우저로 열어 실제 조작(키보드 이벤트, 스와이프 터치 이벤트, 온스크린 버튼 클릭, 다크모드 토글, 새 게임,
375px 모바일 뷰포트 리사이즈)한 결과를 관찰하는 방식으로 진행했다.
(참고: 처음에 `file://`로 직접 열었을 때는 브라우저 도구가 프로젝트 폴더 밖 파일을 정적 스냅샷으로만 렌더링해
`script.js`가 전혀 실행되지 않았다 — 이는 검증 도구 자체의 제약이며 게임 코드의 문제는 아니다. 이후 로컬 정적
서버로 전환해 정상적으로 검증했다.)

## spec.md "7. 검증 계획" 항목별 결과

1. **타일 이동/병합** — 정상.
   - 4방향(좌/우/상/하) 모두 `moveLeftBoard`를 축으로 한 회전/전치 조합이 올바르게 동작함을 실제 조작으로 확인.
   - 예: 위로 스와이프 시 같은 열의 인접한 두 `2`가 정확히 `4` 하나로 병합되고, 서로 다른 값(`2`,`4`)은 병합되지
     않고 위치만 이동함을 확인.
   - 코드상 `moveLeftRow`가 한 패스로만 처리되어(병합 결과를 다시 순회하지 않음) 연쇄 병합(`2,2,4` → `4,4` →
     `8`)이 발생하지 않는 구조임을 확인. (2048 타일을 실제로 만들기는 매우 많은 조작이 필요해 이 부분은 로직
     검토로 대체 — spec.md 7번 항목이 허용한 방식)

2. **스폰 로직** — 정상.
   - 유효한 이동(`moved === true`) 직후에만 `spawnTile()`이 호출되어 새 타일이 1개 생기는 것을 확인.
   - 이미 완전히 밀린 상태에서 같은 방향키를 반복 입력해도(`moved === false`) 보드와 점수에 변화가 없고 새
     타일도 생기지 않음을 실제 조작(동일 방향 10회 연속 입력)으로 확인.

3. **승패 조건** — 코드 검토로 확인 (실제 플레이로 2048 타일을 만들기는 비현실적이라 spec.md가 허용한 대체
   방식 사용).
   - `checkGameState()`가 매 `spawnTile()` 직후 호출되고, `board.some(v => v >= 2048)`이면 `hasWon = true` +
     승리 오버레이, 그 다음에만 `canMove()`(빈 칸 또는 인접 동일값 존재 여부)로 패배를 판정하는 순서가
     spec.md 3.4와 일치함을 확인.
   - 오버레이 자체의 마크업/CSS는 `win-overlay.hidden = false`로 강제 노출시켜 보드 위에 정확히 겹쳐서
     중앙 정렬로 표시되는지, "다시 시작" 버튼이 존재하는지 시각적으로 확인함 (스크린샷으로 라이트/다크 모드
     양쪽에서 가독성 확인).
   - `applyMove()`가 함수 시작부에서 `if (isGameOver || hasWon) return;`으로 막고 있어, 오버레이가 떠 있는
     동안(승리/패배 플래그가 설정된 이후) 재시작 외 입력이 무시되는 spec.md 6번 요구사항과 일치함을 코드로
     확인.

4. **점수 갱신** — 정상.
   - 병합 시 두 타일 합만큼 정확히 점수가 오르는 것을 확인 (예: `2+2` 병합 시 점수 +4).
   - `best`가 `localStorage`(`best-score` 키)에 저장되고, 페이지를 새로고침해도 유지됨을 확인. 또한 "새 게임"
     클릭 시 `score`는 0으로 초기화되지만 `best`는 유지됨을 확인.

5. **모바일 터치** — 정상.
   - 스와이프 제스처: `touchstart`/`touchend` 좌표 차이가 임계값(30px) 미만이면 이동이 무시되고, 임계값 이상이면
     올바른 방향으로 이동/병합됨을 확인.
   - 온스크린 방향 버튼: `.controls-pad`에 위임된 클릭 핸들러가 각 버튼의 `data-direction`을 읽어 동일한
     `applyMove()`를 호출함을 확인, 실제 클릭으로 이동 동작 확인.

6. **반응형 레이아웃** — 정상.
   - 뷰포트를 375×812(모바일)로 리사이즈한 스크린샷에서 점수판이 세로로 쌓이고 "새 게임" 버튼이 전체 너비로
     바뀌며, 4x4 보드와 온스크린 방향 버튼이 겹치거나 잘리지 않고 화면 안에 정상적으로 표시됨을 확인.

7. **다크모드** — 정상.
   - 수동 토글 클릭 시 `data-theme` 속성과 `localStorage`(`theme-2048`) 값이 함께 바뀌는 것을 확인.
   - 새로고침 후에도 저장된 테마가 유지되는 것을 확인 (`light`로 토글 후 새로고침 → `light` 유지).
   - `prefers-color-scheme: dark` 미디어쿼리 블록과 `[data-theme="dark"]` 강제 오버라이드가 CSS에 함께 정의되어
     있어 시스템 설정 자동 반영 + 수동 토글이 공존하는 구조임을 코드로 확인.

8. **재시작 버튼** — 정상.
   - "새 게임" 클릭 시 보드가 초기화되고 타일 2개가 새로 스폰되며 점수가 0으로 초기화됨을 확인 (최고 점수는
     유지).

## 콘솔 에러

전체 조작 과정에서 콘솔 에러/경고 없음.

## 코드 구조 대조 (spec.md 2~6절)

- 파일 구성(`index.html`/`style.css`/`script.js` 3개, 블로그 본체 자원 미참조), CSS 커스텀 프로퍼티 기반
  라이트/다크 테마, 타일 값별 색상 클래스(`tile-2`~`tile-2048`, `tile-super`), 좌측 밀기로 통일한 4방향 처리
  구조 등이 spec.md와 일치함을 확인.
