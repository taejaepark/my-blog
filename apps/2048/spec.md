# 2048 게임 구현 계획 (spec)

## 1. 게임 개요

- 4x4 그리드 위에서 진행되는 숫자 타일 퍼즐 게임.
- 게임 시작 시 빈 칸 중 2곳에 타일이 랜덤 스폰됨 (값은 2 또는 4, 확률은 2가 90%, 4가 10%).
- 플레이어가 방향키(↑↓←→) 또는 모바일 터치 입력으로 "밀기" 동작을 하면, 해당 방향으로 모든 타일이 이동하며 같은 값을 가진 인접 타일끼리 만나면 하나로 합쳐짐(값은 두 배가 됨).
- 한 번의 이동에서 하나의 타일은 최대 한 번만 병합됨 (연쇄 병합 없음 — 예: 2,2,4가 한 줄에서 왼쪽으로 밀리면 4,4가 되고, 다시 8로 합쳐지지 않음).
- 이동이 실제로 하나 이상의 타일 위치/값 변화를 만들어낸 경우에만 새 타일을 하나 스폰함. 아무 변화가 없는 방향키 입력은 무시함.
- **승리 조건**: 2048 값의 타일이 등장하면 승리 메시지를 표시. (계속 플레이할지 여부를 묻는 등의 확장 없이, 승리 메시지 표시 후에도 게임판 조작은 계속 가능하게 두거나 재시작만 유도 — 과설계 방지를 위해 승리 시 오버레이 메시지 + 재시작 버튼만 노출하고, "계속하기" 별도 기능은 만들지 않는다.)
- **패배 조건**: 그리드가 가득 찼고, 어느 방향으로도 이동/병합이 불가능한 상태가 되면 패배(게임 오버) 메시지를 표시.

## 2. 파일 구조

`/apps/2048/` 폴더 안에 아래 3개 파일만 생성한다. 블로그 본체의 다른 파일(assets/css/style.css, assets/js/theme.js 등)은 일절 참조하지 않고, 이 앱은 완전히 자체 완결적이어야 한다.

- `index.html`: 게임 마크업 (그리드 컨테이너, 점수판, 재시작 버튼, 다크모드 토글 버튼, 모바일용 온스크린 방향 버튼, 승리/패배 오버레이). `style.css`, `script.js`를 상대 경로로 로드.
- `style.css`: 레이아웃, 타일 색상, 다크모드 변수, 반응형 스타일 전부 포함.
- `script.js`: 게임 상태, 입력 처리(키보드/터치), 이동·병합 로직, 점수 계산, 렌더링, localStorage 최고점수 처리를 모두 포함하는 순수 바닐라 JS. 외부 라이브러리/CDN 사용하지 않음 (이 게임 로직에는 마크다운 파서 등 별도 라이브러리가 필요 없으므로 전부 자체 구현).

## 3. 게임 로직 설계

### 3.1 상태 표현
- `board`: 4x4 2차원 배열(`Array(4).fill(null).map(() => Array(4).fill(0))`). 값 `0`은 빈 칸을 의미하고, 그 외 값은 타일의 숫자.
- `score`: 현재 점수를 담는 숫자 변수.
- `best`: localStorage에서 불러온 최고 점수.
- `isGameOver`, `hasWon`: 게임 종료/승리 여부를 나타내는 불리언 플래그(중복 오버레이 표시 방지용).

### 3.2 이동/병합 알고리즘
- 방향(왼쪽/오른쪽/위/아래) 입력을 "왼쪽으로 밀기" 로직 하나로 통일해서 처리한다. 위/오른쪽/아래 입력은 보드를 회전 또는 전치(transpose)한 뒤 동일한 "왼쪽 밀기" 함수를 적용하고, 처리 후 다시 원래 방향으로 되돌리는 방식으로 구현하여 4방향 로직 중복을 피한다.
- "왼쪽 밀기" 처리는 그리드의 각 행(row)에 대해 다음을 수행:
  1. 0이 아닌 값들만 순서대로 추출.
  2. 왼쪽부터 인접한 두 값이 같으면 하나로 합치고(값 2배, 점수에 합산값 가산), 합쳐진 타일은 이번 이동에서 다시 병합 대상이 되지 않도록 표시.
  3. 남은 칸은 0으로 채움.
- 이동 전/후 보드를 비교하여 변경 여부(moved)를 판정 — 하나라도 값이나 위치가 바뀌면 `moved = true`.

### 3.3 타일 스폰 로직
- `moved === true`인 이동 직후에만 실행.
- 현재 빈 칸(`0`) 좌표들을 모두 수집한 뒤 그중 하나를 무작위로 선택.
- 선택된 칸에 90% 확률로 2, 10% 확률로 4를 배치.
- 게임 시작 시에는 이 스폰 로직을 2회 호출.

### 3.4 승패 판정 시점
- 매 타일 스폰 직후에 판정 수행.
- **승리**: 보드 내에 값이 2048 이상인 타일이 존재하고 아직 `hasWon`이 표시되지 않았다면 승리 오버레이 표시, `hasWon = true`로 설정.
- **패배**: 빈 칸이 하나도 없고, 4방향 중 어느 쪽으로 밀어도 `moved`가 발생하지 않는 상태(모든 인접 칸의 값이 서로 달라 병합도 불가능)이면 패배 오버레이 표시.

## 4. 점수판 설계

- 현재 점수(`score`)를 화면 상단에 항상 표시.
- 점수 계산 규칙: 두 타일이 병합될 때마다 병합 결과 값(두 타일 값의 합)을 `score`에 더함. 예: 2+2가 합쳐져 4가 되면 점수 +4.
- 최고 점수(`best`)는 필요하다고 판단해 포함한다: `localStorage`에 `best-score` 키로 저장하고, 매 이동 후 `score > best`이면 `best`를 갱신해 저장 및 표시. 최고 점수도 현재 점수 옆에 함께 표시.
- 재시작 시 `score`는 0으로 초기화되지만 `best`는 유지됨.

## 5. UI/레이아웃

- **타일 색상**: 숫자 값에 따라 배경색을 CSS 클래스(`tile-2`, `tile-4`, `tile-8`, … `tile-2048`, 그 이상은 공통 클래스 `tile-super`)로 구분. 값이 커질수록 진한 색으로, 글자색은 작은 값(2, 4)은 어두운 텍스트, 그 이상은 밝은 텍스트를 사용해 대비 확보.
- **다크모드**: 블로그 본체와는 독립적으로 이 앱 자체적으로 다크모드를 지원한다(파일을 공유하지 않으므로). 방식은 블로그 본체와 동일한 패턴을 따름: CSS 커스텀 프로퍼티(`--bg`, `--text`, `--board-bg`, `--tile-empty-bg` 등)를 `:root`에 정의하고, `prefers-color-scheme: dark` 미디어쿼리로 자동 전환 + `data-theme` 속성을 이용한 수동 토글 버튼을 `index.html`에 둔다. 토글 상태는 `localStorage`(`theme-2048` 키 등 이 앱 전용 키)에 저장해 재방문 시 유지.
- **반응형/모바일 레이아웃**: 그리드는 `vw` 기반 또는 `max-width`를 가진 정사각형 컨테이너로 구성해 화면 폭에 맞게 축소. 좁은 화면(모바일)에서는 게임판이 뷰포트 너비에 맞춰 줄어들고, 폰트 크기도 타일 크기에 비례해 조정(예: `clamp()` 사용). 점수판과 버튼들은 세로로 쌓이는 레이아웃으로 전환.
- **재시작 버튼**: 상단에 "새 게임" 버튼을 두어 클릭 시 보드/점수를 초기화하고 새로 2개의 타일을 스폰.

## 6. 입력 처리

- **키보드**: `keydown` 이벤트에서 화살표 키(`ArrowUp/Down/Left/Right`)를 감지해 해당 방향 이동 함수 호출. 방향키의 기본 스크롤 동작은 `preventDefault()`로 막음.
- **모바일 터치**: 두 가지 방식 모두 제공.
  1. **스와이프 제스처**: 게임판 영역에서 `touchstart`/`touchend` 좌표 차이를 계산해 수평/수직 중 더 큰 변위 방향으로 이동 판정(일정 임계값 이상 이동했을 때만 스와이프로 인식해 오탐 방지).
  2. **온스크린 방향 버튼**: 게임판 아래에 상/하/좌/우 4개의 버튼을 배치해 클릭/탭 시 동일한 이동 함수를 호출. 스와이프가 익숙하지 않은 사용자를 위한 보조 수단.
- 게임 오버/승리 오버레이가 떠 있는 동안에는 재시작 외의 입력을 무시.

## 7. 검증 계획

구현 완료 후 아래 항목을 확인하여 완성 여부를 판단한다.

1. **타일 이동/병합**: 4방향 각각에 대해 타일이 올바르게 밀리고, 같은 값의 인접 타일이 정확히 한 번만 합쳐지는지 확인 (연쇄 병합이 발생하지 않는지 포함).
2. **스폰 로직**: 유효한 이동 후에만 새 타일이 하나 생기고, 변화 없는 이동(막힌 방향)에서는 새 타일이 생기지 않는지 확인.
3. **승패 조건**: 2048 타일 등장 시 승리 오버레이가 뜨는지, 더 이상 이동 불가 상태에서 패배 오버레이가 뜨는지 확인.
4. **점수 갱신**: 병합 시 점수가 정확한 값만큼 오르는지, 최고 점수가 localStorage에 저장되고 재방문/재시작 후에도 유지되는지 확인.
5. **모바일 터치**: 스와이프 제스처와 온스크린 버튼 양쪽 모두로 정상 이동이 되는지 확인.
6. **반응형 레이아웃**: 좁은 화면(모바일 너비)에서 게임판과 버튼이 겹치거나 잘리지 않고 읽기 편한지 확인.
7. **다크모드**: 시스템 설정(`prefers-color-scheme`) 자동 반영과 수동 토글 버튼이 모두 정상 동작하고, 토글 상태가 새로고침 후에도 유지되는지 확인.
8. **재시작 버튼**: 클릭 시 보드/점수가 초기화되고 새 타일 2개가 스폰되는지 확인.
